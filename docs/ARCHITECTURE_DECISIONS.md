# Architecture decisions

| ID | Decision | Why | Status |
|---|---|---|---|
| ADR-001 | Native GNS3 on the bare-metal Ubuntu host (no GNS3 VM / EVE-NG) | Host is bare metal with working VT-x/EPT; an extra hypervisor layer only costs RAM | Accepted |
| ADR-002 | GNS3 **2.2.61** from the official PPA, pinned with `apt-mark hold` | Only line packaged for noble with matching ubridge; 3.0.6 is pip-only and API v3 is less supported by tooling | Accepted |
| ADR-003 | OPNsense 26.7 **nano** image, provisioned over the serial console from its own factory `config.xml` | Pre-installed, serial console → scriptable; transforming the dumped config keeps image keys out of Git and matches the 26.7 schema exactly | Implemented + verified |
| ADR-004 | Modular monolith, hexagonal: `domain` / `ports` / adapters; SQLAlchemy only under `persistence` (ruff TID251 enforces it) | Clean boundaries without microservice overhead on 16 GB | Implemented |
| ADR-005 | SQLite (WAL) + Alembic migrations; JSON bodies + indexed columns | Lab-appropriate; portable to PostgreSQL by changing `AFW_DATABASE_URL` | Implemented |
| ADR-006 | Level-triggered enforcement: backends receive full desired state; ownership-aware expiry | Duplicates, overlaps, restarts and reboots become idempotent | Implemented + tested (memory backend) |
| ADR-007 | Client identity only from the WAF TCP peer; WAF overwrites XFF/X-Real-IP/X-Request-ID; app trusts headers only from WAF IP | Prevents forged-header bans | Implemented in code/templates |
| ADR-008 | WAF uses host networking inside WAF01 (`ip_unprivileged_port_start=443` on WAF01 only) | Avoids Docker NAT altering the observed source IP | Verified: true client IP in WAF and app logs |
| ADR-009 | OPNsense: fixed rules + external alias `AFW_BLOCK_WEB`; heartbeat alias `AFW_HEARTBEAT` + FW-local watchdog flush | Uses documented alias_util API; bounded outage behaviour without a controller | Verified on FW01: flush after 106 s without heartbeat |
| ADR-010 | ML features exclude WAF/IDS signals, source IP, zone, labels | Keeps ML independent of CRS; avoids leakage | Implemented |
| ADR-011 | Detectors: robust stats (M1), Isolation Forest (M2), River HST (online/shadow comparator) | Lightweight, explainable via occlusion attribution | Implemented; comparison needs lab data |
| ADR-012 | Adaptation: frozen trusted profile; reputation-gated shadow stream; candidate rebuilt from raw observations; evaluation gate (source-share cap, sensitive-feature limits, attack-recall regression, FP comparison); human promotion; rollback | Learns legitimate change without letting attackers define "normal" | Implemented; Scenario C not yet run |
| ADR-013 | Risk = capped additive evidence score, never a probability; ML/stat count as one corroborating category; blocks need ≥2 independent categories | Anomaly alone cannot authorize traffic changes | Implemented + tested |
| ADR-014 | MCP via official SDK `mcp` 2.3.0 (`MCPServer`) as a client of the REST API with a `channel=mcp` token | Single validation/enforcement path | Implemented + verified with a real MCP client and extended with GNS3 tools (see ADR-025) |
| ADR-016 | Golden Ubuntu image baked once (QEMU user-net + cloud-init) with all runtimes, WAF image pulled by digest; per-node identity via NoCloud seed ISO; linked clones | Lab guests need no Internet; reproducible; RAM/disk efficient | Implemented |
| ADR-017 | Least-privilege OPNsense API user for the controller; a separate root "provisioner" key exists only for host-side setup | A stolen controller key can only change alias membership and read/delete states | Verified (filter API → 403) |
| ADR-018 | Lab PKI: one lab CA (`~/.config/afw/pki`), leaf certs with IP SANs; all controller→device TLS verified | No `verify=False` anywhere in the data path | Implemented |
| ADR-019 | Ansible (`lab/ansible`, ansible-core as dev dep) for guest configuration; secrets generated on the host and copied, never templated from Git | Idempotent, reviewable; matches the team plan | Implemented (`changed=0` on re-run) |
| ADR-020 | WAF evidence = CRS-blocked or anomaly ≥ 5 (PL1 threshold); score from rule severities; WAF sensor's own traffic excluded | Live lab showed lone warnings (920350) inflating benign risk | Implemented + tested |
| ADR-021 | Suricata in IDS (pcap) mode on client-zone interfaces only; HOME_NET = protected zones; EVE via syslog-ng TCP to CTRL01; configured through the OPNsense API with the provisioner key | Inbound signatures apply to client→service traffic; no inline-IPS risk to availability | Verified (ET SCAN 2010937 end to end) |
| ADR-022 | Country policies: real only with a GeoIP DB (none in the lab); otherwise a config-declared, clearly labelled simulated map; inbound only; expanded to source blocks on OPNsense with read-back of every member | Satisfies the optional MCP extension without fabricating geography | Verified on FW01 |
| ADR-015 | Dashboard: static HTML/JS served by FastAPI, no CDN, all strings escaped | Offline demo; attacker-controlled strings reach the page | Implemented + rendered in headless Chromium (every panel validated with real backend data, 0 console/page errors); 2 bugs fixed; deployed to CTRL01 |
| ADR-023 | Controller API TLS: `afw serve` serves HTTPS when `AFW_TLS_CERT`/`AFW_TLS_KEY` are set (lab-CA-signed `CTRL01` leaf cert, IP SAN); clients verify via `AFW_API_CA`. **Opt-in** (`controller_tls` Ansible flag); the lab **defaults to HTTP** | Capability reuses the lab PKI (ADR-018) and is verified, but operator access is via an SSH tunnel (already encrypted); a host-pinned self-signed cert breaks tunnelled `localhost` access, so HTTPS is not forced | Implemented + tested (HTTPS+CA 200, verify-fail without CA); lab runs HTTP |
| ADR-024 | Decision explanations are self-contained: full detector outputs (incl. occlusion attributions) are snapshotted onto the `RiskAssessment` at decision time, not re-queried from the retention-pruned detections table | `explain` must stay faithful for audit/viva after the 7-day detection purge; assessments are retained | Implemented + tested (survives a full detection purge) |
| ADR-025 | One `afw` MCP server with two backends: AI/policy/OPNsense/WAF tools call the controller REST API (`channel=mcp` token, HTTPS, lab-CA verified) so every mutation re-uses the validator/enforcement/audit path; GNS3 lab-infrastructure tools call the host GNS3 API directly. Typed tools only, no raw shell; read / operational / mutation tools separated; CTRL01 never power-cycled via MCP | Natural-language lab management without a second control plane or a shell-exec escape hatch; the safety validator is never bypassed | Implemented + verified with a real MCP client (26 tools) and registered in Claude Code (`.mcp.json`, Connected) |
| ADR-026 | Professional GNS3 canvas layout + zone annotations applied idempotently from code (`afw lab layout`), not hand-placed in the GUI | Reproducible, readable top-to-bottom traffic-flow canvas that survives reopen; presentation kept separate from the authoritative `topology.yaml` | Implemented (13 nodes, 5 colour-coded zones, role symbols) |
| ADR-027 | **Provenance-aware corroboration.** A behaviour detection counts as independent corroboration of AUTH/WAF evidence only if the detector stays above its threshold with the features derived from that evidence occluded to the profile median (counterfactual, computed by the model itself). Map: AUTH -> login_rate, auth_fail_frac, distinct_usernames, client_err_frac (401s); WAF -> client_err_frac (403s); IDS shares no features. Non-independent behaviour still adds risk points but is listed in `discounted_categories` and cannot satisfy the 2-category block rule (the engine falls back to a bounded rate limit) | Phase 0 audit: one failed-login stream produced both AUTH evidence and an auth-feature anomaly, satisfying ADR-013 from a single event stream. A hand-made feature-family rule would be arbitrary; the counterfactual uses the actual model. Alternative rejected: dropping behaviour+AUTH corroboration entirely (would ignore genuinely independent volume/shape anomalies) | Implemented + 7 unit tests (`tests/unit/test_evidence_independence.py`); synthetic brute force still blocked because its request rate is independently anomalous |
| ADR-028 | **Online shadow challenger.** A deep copy of the trusted HST is updated prequentially (score, then `learn_one`) only from windows passing a two-stage gate (stage 1 provenance/joined/malformed/protected/negative-evidence/sensitive-range/overlap/duplicate/taint; quarantine with delayed admission; stage 2 late taint, tenure, per-source rate and share caps, population, multi-source corroboration of anomalous windows by behavioural similarity, revised after the M4 experiment found name-based matching let benign drift vouch for poison). Atomic sha256-verified checkpoints committed with the learned-window ledger in one transaction; persisted taint. Shadow only: no enforcement influence, no promotion before M3 | Phase 0: no runtime learning existed. Unrestricted online learning is a poisoning channel. HST is natively incremental in River; IF/robust stats are batch. Alternatives rejected: periodic batch retrain on all traffic (no poisoning control, overlapping windows inflate n), learning into the champion (unsafe) | Implemented + 27 unit tests (`tests/unit/test_online_learning.py`); live on CTRL01; real-data replay `afw experiment online-replay` |
| ADR-029 | **Authenticated telemetry provenance.** WAF01/APP01 ship logs over rsyslog gtls with per-sensor client certs from the lab CA (`x509/name`, pinned `ctrl01.lab.afw`); the controller maps client CN to a sensor role and drops lines whose kind does not match the role. Observations are AUTHENTICATED only when every joined part arrived authenticated; replayed datasets are CURATED; everything else UNVERIFIED and never learned from. Stable request ids deduplicated before windowing | Plaintext UDP/TCP syslog lets any lab host forge sensor lines, which would make online learning a poisoning channel. Alternative rejected: source-IP allowlist only (spoofable on shared segments, not cryptographic) | Implemented + 8 unit tests incl. real mTLS handshakes; live: 8/8 observations authenticated, sensors refused on plaintext 5515 (isolation 37/37) |
| ADR-030 | **Champion/challenger lifecycle.** A challenger checkpoint is evaluated on recorded holdout runs (min learning, no holdout leakage, clean ledger, holdout size, benign FPR not worse at a calibrated threshold, attack recall not regressed on *real* labelled attack runs, sensitive-feature invariance); only a fully passing evaluation freezes a CANDIDATE. Promotion is a human admin action with freshness, integrity and champion-unchanged checks; a probation rolls back automatically to the parent on an excessive live anomalous rate or operator false-positive reports | Online learning without a promotion gate is either useless (never trusted) or unsafe (trusted blindly). Automatic rollback is safe because it only returns to a previously trusted model; automatic promotion is not, so it does not exist. Alternatives rejected: auto-promote on shadow agreement (agreement is not correctness; poisoned challengers can agree), accepting synthetic attack data for the recall gate (would make the gate decorative) | Implemented + 20 unit tests + API test (`tests/unit/test_challenger_lifecycle.py`), mutation-checked; live gate externally blocked on real labelled attack runs |
| ADR-031 | **Telemetry v2.** Envelope `schema_version`/`received_at`; content-derived IDS event ids with idempotent storage (a replayed alert line counts once); IDS-only assessments for sources without HTTP windows, capped at WATCH; 30 s sensor heartbeats over the mTLS channel with per-role staleness feeding degraded evidence; bounded TCP retransmission on sensors | Phase 0 §3.3 gaps, plus two defects found while verifying: random IDS ids let replayed alerts inflate risk points, and after a controller restart the sensors silently stalled for about 55 min (FW01 drops the stale flow; the controller could not tell stuck from idle). Alternatives rejected: RELP (needs a RELP server on the controller; deferred, residual loss documented), blocking or rate limiting on IDS alone (single-category evidence, ADR-013) | Implemented + 8 unit tests (`tests/unit/test_telemetry_v2.py`), mutation-checked; live: envelope v2 on IDS and HTTP, IDS-only assessment of an ATK01 scan, unattended sensor recovery after controller restarts (`artifacts/evidence/m5-2026-10-27/`) |
| ADR-032 | **Attack-evaluation harness without traffic generation.** A validated scenario registry (lab-owned target allowlist; management and database networks always refused; attackers restricted to ATTACK-zone clients; max duration at most 1 h), a ground-truth run journal (one active run, named operator, phase marks), a kill switch and watchdog that stop ATK01 via the GNS3 API, manifests generated from the journal, and cross-run evaluation with run-level bootstrap CIs that refuses synthetic data | Attack metrics need trustworthy labels and independent runs; per-window metrics from one run overstate confidence. The team performs authorized attacks with standard tools; the project supplies safety rails and measurement. Alternatives rejected: an in-project attack generator (out of scope for this project's safety constraints), synthetic attack data for Gate B (not evidence), window-level CIs (windows within a run are not independent) | Implemented + 14 unit tests (`tests/unit/test_scenario_harness.py`), 10/10 mutations caught; Gate B BLOCKED-EXT on team runs (`docs/engineering/M6_ATTACK_EVALUATION.md`) |
| ADR-033 | **Real GeoIP is lookup and preview only.** DB-IP Country Lite (CC BY 4.0) installed with recorded source, release month and SHA-256 (verified at load); stale 45 days after release; private/reserved space never has a country; a preview shows a country's networks and which observed sources it would cover; real-country enforcement is refused by the validator | Country policies were simulated-only (Phase 0). Real lookups add enrichment and an honest preview. Enforcement would need network-granular desired state, bulk aliases and new FW01 rules per direction, and inbound policies could only be verified by alias read-back (no inbound real-country traffic reaches the lab; outbound egress exists but is not observed by the controller). Alternatives rejected: MaxMind GeoLite2 (account and licence key needed), accepting real policies with an empty member set (would never verify or would look enforced), adding thousands of CIDRs to the host block alias one call at a time | Implemented + 6 unit tests + API test, 7/7 mutations caught; installed on CTRL01 (`docs/engineering/M7_GEOIP.md`) |

## Reuse register (ADOPT / EXTEND / REFERENCE / REJECT)

| Component | Decision | Note |
|---|---|---|
| OPNsense + pf + Suricata | ADOPT | network enforcement, IDS evidence |
| OWASP CRS ModSecurity nginx image (LTS tag) | ADOPT | pinned by digest |
| scikit-learn IsolationForest, RobustScaler | ADOPT | |
| River (HalfSpaceTrees, ADWIN) | ADOPT | shadow learner + drift |
| Official MCP Python SDK | ADOPT | v2 API |
| Alembic / SQLAlchemy / FastAPI / Pydantic | ADOPT | |
| `oxlorg.opnsense` Ansible collection | REJECT (for now) | FW baseline done via console + config transform; controller uses 2 documented endpoints |
| gns3fy | REFERENCE | own thin client written (`src/afw/lab/gns3.py`, API v2) |
| `gns3-mcp` 0.54.2 (ChistokhinSV, MIT, community) | REJECT | requires GNS3 **v3** API; we pin 2.2/API v2. Instead we ship our own typed GNS3 MCP tools (`src/afw/mcp/gns3_tools.py`) over our v2 `Gns3Client`, integrated with the controller's AI/policy tools in one server (ADR-025). Re-evaluate on a 3.x migration |
| go-ftw | ADOPT (planned) | WAF regression tests |
| CrowdSec | REFERENCE | overlapping control plane; not adopted |
| Kubernetes / Kafka / ELK / Wazuh | REJECT | resource cost on 16 GB |
