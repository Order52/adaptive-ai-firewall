### 3.2 Generator v2 and a generator finding

`traffic/benign_personas.py` gained `AFW_PERSONA_SET=v2`, with legitimate archetypes:
- casual and regular users;
- forgetful users, who mistype a password up to 3 times;
- power users;
- households of 2–4 accounts behind one address;
- stale links that return 404;
- slow users;

Two findings came out of building it:
- The v1 generator omits the required `city` field, so **every v1 booking returned

Both inflate legitimate client errors in all earlier data. They are recorded in the
protocol, not hidden. A generator bug where the final pause overran the run time was
also fixed.

### 3.3 Amendment A1 (before selection data)

A smoke test of the harness on P1 data showed every candidate at 1.0 on the must-detect
cases. The selection rule therefore could not distinguish candidates on the actual
question: does sensitivity silently weaken under adaptation?

A1 adds a stress test. Each candidate's adaptable thresholds are recalibrated with 3 %
sub-must attack-shaped windows labelled as benign. Selection then uses the lower of the
nominal and stressed rates, and a fifth final criterion is added. The smoke result was
a code check, not a conclusion: stressed R2 0.57, D 0.78, S 1.0.

### 3.4 New modules

- `src/afw/ml/regression_suite.py`: synthetic feature-level malicious-behaviour cases
  (brute force, stuffing, enumeration, IDOR, scraping), added to real benign base
  windows. They are labelled SYNTHETIC and **send no traffic**. They measure
  sensitivity regression only, never attack detection.
- `src/afw/ml/security_path.py`: Wilson lower-bound fractions and a one-sided security

- `src/afw/ml/p6_study.py`: training, evaluation, sensitivity and stress for each

## 4. SV-1: evidence independence was wrong, now fixed (item 8, ADR-039)

**Defect, demonstrated.** ADR-027 judged a behaviour anomaly "independent" of AUTH/WAF
evidence by masking the evidence features (occlusion). The measurement added synthetic
failed logins to real benign windows that the detector had scored normal, so the true
answer is always "dependent". Occlusion still called these anomalies independent in up
to:
- **76 %** of cases for v2 robust statistics;
- 13 % for v2 Isolation Forest;
- 33 % for v2 HST;
- 44 % for a P6 Isolation Forest.

The cause: the same requests also change request rate, route mix and timing, which
masking leaves in place. Occlusion also called genuinely independent anomalies (brute
force plus scraping) dependent in up to 100 % of cases.

**Fix.** Feature extraction now also records each window's values *without* the requests
behind the evidence (`FeatureVector.residuals`). A behaviour anomaly is independent only
if that residual window is still anomalous. Older stored vectors fall back to occlusion.

**Result** (offline, `p1-val` bases, 55–65 cases per detector): residual false
independence is 0 in every cell. Evidence: `artifacts/evidence/p6-2026-10-28/sv1-p1val.json`.

**Behaviour change, stated openly.** A source whose only abnormality is failed logins
now has one corroborating category, so it gets a strict rate limit, not a block. Brute
force plus another independent signal is still blocked. The closed-loop test now checks
both cases. The team's brute-force runs should confirm this live.

## 5. Attack-run preparation (item 5)

- **`afw dataset validate <id>`** exits 1 on any FAIL. It checks:
  - integrity, counts, time range and repeated request ids;
  - unlabelled sources, and addresses labelled both benign and attack;
  - attackers outside the ATTACK zone or without an attack type;
  - attack data marked as training data, and synthetic test data;
  - overlap with another split.

  It warns on:
  - silent labelled sources and attacker traffic outside its label window;
  - weak provenance and aborted runs;
  - same-split subsets and reused benign addresses (named per dataset).

  On the real datasets it confirmed an already-documented P1 fact: five of the six
  "new" `real-drift-hold` addresses also appear in v2's training data.
- **Runbook** (`P3_TEAM_ATTACK_RUNBOOK.md`):
  - a validate step after every capture;
  - a free address range (.200–.249; P6 uses .90–.197);
  - isolation count 41/41;
  - the ADR-039 expectation for pure brute force.

## 6. Four-way comparison harness (item 6)

- **New evaluation arms**, alongside M0 static and M2 frozen ML:
  - S-ML: robust statistics plus an online HST that learns through the live admission
    gate, scored before it learns from each window.
  - HYB: M2's detectors plus the same online HST.

  The learners never see labels. These arms are evaluation counterfactuals only: they
  cannot be selected as a live strategy, and HST stays shadow live.
- **Warm-up.** The live gate needs 30 min of source tenure and a 10 min quarantine, so a
  fresh learner learns nothing within a short run. Optional warm-up datasets (benign,
  ending before the run, enforced by the command) give it realistic history. Learning
  during warm-up and during the run is reported separately.
- **Defect found and fixed.** Datasets did not store IDS alerts, so `experiment evaluate`
  replayed every arm **without IDS evidence**. Capture now stores the labelled sources'
  IDS alerts, sha256-checked, and evaluation and validation use them.
- The protocol and fairness rules are predeclared in runbook §4.1. Results need the
  team's runs (BLOCKED-EXT).

## 8. Rollback reliability (item 8, ADR-040)

Demonstrated by injecting failures at the database layer:
- A failure at the second of two status writes left **no active HST** after a promotion
  or rollback.
- An automatic rollback with a corrupted parent artifact raised on every controller tick,
  while the breached model stayed active.
- A failure at any of the five writes of a **trusted-profile promotion** left one of
  three states:
  - no trusted profile;
  - a trusted profile with no models (ML detection off);
  - a trusted profile with robust statistics only.

Fixed:
- All status switches, and the profile switch together with its enforcing models, are
  now single transactions.
- Promotion records its probation first, and an orphaned probation is closed on the next
  check.
- A failed automatic rollback still rejects the breached model and audits the failure.

There are 12 new tests, and non-atomic mutations of both fixes are caught.

## 9. Other item 8 checks

- **GeoIP.** A database that goes stale during an active real-country policy can affect
  that policy for at most its duration, which is capped at 1 h. New policies are refused
  on stale data. No defect was demonstrated; the bound is documented.
- **IDS liveness.** FW01's heartbeat checks only that a Suricata process exists, so a
  hung engine might still appear alive. **Not yet demonstrated.** Planned test between
  Phase D and E, with no data collection running: pause Suricata briefly and see whether
  heartbeats continue.
- **RELP persistence.** A crash can lose lines that were acknowledged but not yet
  processed (normally under a second; ADR-038). Planned measurement between phases: a
  kill -9 of the controller during dedicated benign traffic, comparing WAF request ids
  with the stored observations.
