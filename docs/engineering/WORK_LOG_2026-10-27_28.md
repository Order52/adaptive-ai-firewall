**c. Directional real-country enforcement on FW01 (ADR-036, `2c76304`, `f9c97ef`).**

How it works:
- Only a human (operator or MCP) can request it. It needs a fresh, hash-verified GeoIP
  database and at most 40,000 networks per direction.
- The controller publishes per-direction network lists. FW01's watchdog pulls them
  every 30 s, **only while the controller heartbeat is fresh**. It checks the sha256
  and loads each list atomically with `pfctl -T replace` into `AFW_GEO_IN` or
  `AFW_GEO_OUT`.
- The controller then reads the tables back with its unchanged least-privilege key.
- **Inbound** is blocked on every interface. It is verified by read-back only, so it
  stays `applied_unverified`.
- **Outbound** is rejected from the client zones only. It becomes `enforced` only after
  read-back **and** an egress probe: a connection into the country fails while a
  control target elsewhere succeeds.

Live results:
- **AU outbound (12,265 networks):** enforced. Checked independently over SSH: USR01
  could not reach 1.1.1.1 but still reached 8.8.8.8, APP01 was unaffected, and access
  returned after revoke.
- **KP inbound:** read back, never claimed enforced, rolled back.
- **Fail-safe:** with the controller stopped, the watchdog flushed 12,265 entries.
  USR01 regained access 84 s after the stop, and the block came back within 26 s of
  the restart.

Defects and checks:
- **Defect found live:** OPNsense returns a malformed chunked body for table listings
  of about 5,000 rows or more, which made policies flap. Listings are now paged at
  1,000 rows, and the policy then held for 29 consecutive cycles.
- **Defect found by unit tests:** the control egress target was chosen from the wrong
  set.
- **Mutation check:** 9/9 mutants caught. A new test was added for a mutant that had
  survived.

**d. FW01 IDS-feed heartbeat (ADR-037, `7ea5bb3`).**
- **Before:** a stopped Suricata or a dead FW01 log feed was undetectable.
- **Now:** FW01's watchdog logs a liveness line every 30 s, only while
  `pgrep -x suricata` succeeds. OPNsense forwards only listed program names, so the
  line uses the `suricata` tag with `event_type: "afw_heartbeat"`, which Suricata never
  emits. It counts only on the mTLS `ids` channel, and `ids` now takes part in sensor
  liveness.
- **Live:**
  - the first heartbeat arrived 15 s after install;
  - with Suricata stopped, `ids` went stale and evidence degraded at 154.9 s;
  - after restart it was fresh again within 30 s;
  - lab tests 14/14.
- **Limit:** it proves Suricata runs and its log path reaches CTRL01, not that
  inspection is correct.

**e. RELP over mutual TLS for WAF01/APP01 telemetry (ADR-038, `3cc8cd6`).**
- A new receiver listener on 5516 uses the same certificates, identities and sender
  allowlist as 5514.
- Each line is acknowledged only after it is queued. A full queue holds the
  acknowledgement back (backpressure) for up to 30 s.
- rsyslog resends its whole unacknowledged batch after a reconnect (at-least-once). So
  exact repeats of one of a sensor role's last 8,192 lines are suppressed and counted.
- WAF01 and APP01 switched to `omrelp`. FW01 rules (via the API now, and in
  `config.xml` for new builds), the CTRL01 host firewall and the isolation checks
  cover 5516.

Dead-session test: FW01's pf states for the live connection were killed partway
through 150 numbered lines.

| Channel | Delivered | Lost |
|---|---|---|
| plain TCP (omfwd), baseline | 45 | **105** |
| RELP, three runs | 150 | **0** (17 and 3 resends suppressed in the two later runs) |

- **Regression:** isolation 41/41 (4 new checks), lab tests 14/14, 218 local tests pass.
- **Limits:**
  - An acknowledgement means "queued in memory", so a controller crash can lose
    roughly the last second of lines.
  - FW01 cannot use RELP and keeps a ~100 s loss window, which its heartbeat makes
    visible.

**f. Smaller items.**
- The GNS3 node count was reconciled (16).
- The replay request denominators were fixed.
